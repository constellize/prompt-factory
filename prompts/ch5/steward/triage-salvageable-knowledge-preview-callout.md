**Triage salvageable knowledge in moderately stale memory bank** to determine what remains accurate, what needs minor updates, and what must be archived. Identify accurate entries that still reflect current reality by comparing documentation against actual codebase, validating architectural descriptions match implementation, and confirming patterns documented are patterns used. Mark entries needing minor updates where core information is correct but details have drifted including file paths changed or examples needing refreshing. Archive completely obsolete entries where documented approaches are no longer in use, technologies have been replaced, or features have been removed. Assess salvageability systematically by reviewing each memory bank file, categorizing every entry by accuracy level using five categories of accurate keep as-is, minor updates needed with specific flags, major updates requiring rewrite, obsolete requiring archival, and uncertain requiring validation. Estimate recovery effort realistically calculating time for each category and creating phased recovery plan prioritizing high-value low-effort items first. Treat triage as honest assessment rather than wishful thinking, marking everything but deleting nothing during assessment phase, preserving all content while documenting what needs attention.
